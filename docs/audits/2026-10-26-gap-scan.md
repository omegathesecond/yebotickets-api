## High-priority backlog filed

### Atomic payout transitions

Dashboard task: `task-1793020294159-45mvwy` — Make admin payout status transitions atomic under concurrent decisions.

Evidence: `src/services/payout.service.ts:282` loads an allowed status separately from writes at `approvePayoutRequest`, `rejectPayoutRequest`, and `markPayoutRequestPaid`. Each mutation predicates only on request ID. Two admins can read approved, then paid can be overwritten by a stale rejection. `src/services/settlement.service.ts` counts only paid as paid-out and pending/approved as reserved; rejected releases funds. A stale rejection can therefore make transferred funds withdrawable again. The admin dashboard exposes all these transitions in `admin-dashboard/src/lib/admin-api.ts`.

Required outcome: an atomic conditional transition or request row lock, explicit conflict on a lost race, terminal status protection, and retained reference/audit identity. Regression coverage must interleave paid/rejected and approved/rejected decisions and verify exactly one legal winner plus correct settlement balance. Reuse existing transition and settlement code.

### Durable scanner replay identity

Dashboard task: `task-1793020308064-bfubt4` — Make queued scanner admission replay idempotent after a lost response.

Evidence: `scanner-app/lib/services/offline_store.dart` creates an `opId`; `sync_service.dart:184` calls `confirmCheckIn` without it; `ticket_api.dart:40` sends event/ticket only. `src/services/ticket.service.ts:1823` rejects already-used tickets. If the server commits but its response is lost, the queue correctly retains the operation, but the next replay returns already-used; `sync_service.dart:46` classifies that verdict as permanent and removes the operation with a false conflict.

Required outcome: persist an operation receipt atomically with admission, scoped to authenticated operator/event/ticket. Exact replay returns original success; another operation still conflicts. Cover lost acknowledgement, retry/restart, operation-key misuse and competing scanners. Retain session fencing and unsynced admission preservation. Never accept every already-used ticket as a successful replay.
